## Lock ordering and watcher assessment

| Path | Actual held-lock order | Result |
|---|---|---|
| emit | PUBLISH -> App for capture; App released before emit/disk | Serializes capture and publication. No App -> PUBLISH edge found. Slow cache I/O can delay all publishers and synchronous refresh callers, but does not hold App. Success/retry gap is N01. |
| persist | SAVING -> App for capture; App released before settings disk I/O | Serializes writers. No App -> SAVING edge found. Moving set_settings and settings events outside this transaction introduces R03/R04. |
| apply | App capture completed -> Watch; Watch released before window/autostart work | No simultaneous App/Watch acquisition or reverse Watch -> App edge found. Callback only try_send, so a full channel does not block a watcher holding Watch. |
| watcher overflow | sync_channel(1024), try_send drops on Full; consumer takes <=1024 paths before dedup | Queue-count/cap overshoot repaired. Overflow can omit a provider from that burst; eventual rescan relies on the ticker, not a guaranteed dirty bit. It is not a new lock deadlock. See N08 for byte/work bounds. |
