# Independent adversarial baseline audit

Audited commit: **`f80bc4062ca589a79ef5dbb7a4f45b434b3aa3f7`**, tag **`v0.2.1`**. Audit date: 2026-11-15. Platform used for verification: Windows, Node 24.15.0, Rust/Cargo 1.98.1. Line references below refer to this commit, not to the report commit.

The most consequential verified problems concern the truthfulness of displayed usage and the handling of local data: an expired limit becomes 100% available without verification, timezone offsets are ignored, an unavailable provider can retain old limits indefinitely, and database errors can become zero usage. Provider text also reaches an HTML sink, although the configured CSP materially limits script execution. Windows blur reads outside the window rectangle despite the README's explicit claim to the contrary.

No CRITICAL or HIGH exploit was established. MEDIUM means a reproducible integrity, privacy, or application-availability problem with bounded impact or required local/provider influence; LOW means maintainability, documentation, or assurance debt. This severity assessment does not treat a hypothetical CSP bypass or a compromised provider as demonstrated arbitrary code execution.

## Scope and method

Reviewed read-only: `src-tauri/src/main.rs`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`, `src/main.js`, `src/settings.js`, `src/style.css`, `index.html`, `settings.html`, `.github/workflows/release.yml`, and `README.md`. Repository inventory and build metadata were inspected to establish source/test layout and run the authorized checks. The only authored repository file is this report.

Verification labels distinguish **executed** synthetic reproductions, **source proof** from an explicit code path, and **interleaving** reasoning about concurrent operations. Synthetic Rust probes copied the relevant baseline functions unchanged into a temporary crate outside the repository. JavaScript probes evaluated the actual `left` expression and `body` function in Node's VM. No Tauri application was launched, no real log or credential file was opened, no credential value was printed or copied, and the ignored live network test was not run. Package installation is distinct from provider API testing.

## Reproduction details and impact boundaries

### Timestamp and quota integrity (F03, F05, F06, F09, F14, F15)

The timestamp harness compiled the exact baseline `parse_ts` with rustc. These assertions passed, demonstrating the defects rather than testing a replacement parser:

```rust
assert_eq!(parse_ts("2026-10-01T00:00:00+08:00"), Some(1790812800));
assert_eq!(parse_ts("2026-10-01T00:00:00-05:30"), Some(1790812800));
assert_eq!(parse_ts("2026-02-30T00:00:00Z"),
           parse_ts("2026-03-02T00:00:00Z"));
assert!(parse_ts("2026/10/01X00-00-00garbage").is_some());
```

The parser only inspects fixed digit slices through second 19; it validates neither separators nor the offset suffix. An eight-hour error moves a reset countdown and changes which rolling window contains a record. Existing tests include +00:00, which cannot expose this defect.

For F06 the Node VM supplied `Date.now = () => 200000` and evaluated the actual `const left` declaration. It returned 100 for 94% used with reset=199, and 6 with reset=201. It also returned 150 for used_percent=-50 with reset=0: the UI lacks an upper clamp. Cursor/Copilot parsers clamp percentages, while Claude and Codex do not. Treat provider numeric values as untrusted and validate them before rendering.

For F03, call `parse_claude_usage(&serde_json::json!({}))`: it returns Some with no five_hour or weekly. Poll subsequently forces connected=true, and the UI's metric fallback formats missing tokens as zero. The other three online parsers have stronger minimum-presence checks; they still need failure-state handling rather than a stale-data promise.

For F14, create an empty SQLite database with rusqlite, close it, and call the exact `opencode_row`. Open succeeds, SELECT fails because message does not exist, and both aggregates become `(0,0.0)`. For F15, create `message(time_created INTEGER,data TEXT)`, insert an assistant record at `(now()+86400)*1000` with tokens.input=999 and cost=3, close it and call opencode_row: tokens_5h is Some(999). These probes use synthetic data only.

F09 follows directly from the success/error state machine: seed a Row with a limit, then take the Unavailable branch repeatedly. There is no mutation to its figures, connection state or status, and no age field to let the UI detect it. No live outage was induced. Expired/reset behavior compounds this problem but is independently reproducible without a backend.

### HTML injection and CSP containment (F07)

The exact Cursor input used was:

```json
{"membershipType":"<b id=\"audit-injected\">MARKER</b>","individualUsage":{"plan":{"limit":0}}}
```

The Rust parser returns `<b id="audit-injected">MARKER</b> plan, no included usage`. The actual JavaScript body function returns:

```html
<div class="text-[0.6875rem] text-ink/70"><b id="audit-injected">MARKER</b> plan, no included usage</div>
```

render inserts that output into list.innerHTML. This verifies the data-to-markup path; Node's VM is not a browser DOM and does not establish WebView script execution. An attacker would need control over the provider-derived string/response or another producer of the event payload. An ordinary local log string was not shown to reach this status field.

The declared CSP is `default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; connect-src 'self' ipc: http://ipc.localhost`. With no script-src, default-src supplies the script restriction: remote scripts and ordinary inline scripts/event handlers should be blocked. The unsafe-inline allowance is for styles, not scripts. CSP does not escape text or prevent injected HTML and inline styling, so content spoofing/layout manipulation remains possible. No CSP bypass, token exfiltration, remote code execution or shell access was demonstrated; an end-to-end packaged WebView test is still required.

The five custom commands are exposed by `generate_handler!` (`main.rs:981`); the capability file has core window permissions and no shell/filesystem/HTTP plugin grant. Nevertheless, custom save_settings accepts provider directory paths and triggers Rust-side reads, so absence of a filesystem plugin is not proof that a UI bug cannot influence filesystem access. This is a constrained custom-command surface, not an established raw arbitrary-file-read primitive. Settings paths themselves are rendered with textContent (`src/settings.js:36`), and the Settings innerHTML template uses static metadata, which are useful distinctions from the unsafe status sink.

### Capture geometry, cost, and retention (F08)

For a window rectangle `(100,100)-(370,440)`, ring reads top `(94,94,282,6)`, bottom `(94,440,282,6)`, left `(94,100,6,340)`, and right `(370,100,6,340)`. These rectangles are outside the widget and pass to StretchBlt. They are downsampled to 24x1 or 1x24 and used to decide whether to capture the main patch. This directly contradicts “captures nothing outside its own rectangle” at README:82.

The loop sleeps 50 ms, reads the four strips, then checks the 200 ms/1 s full-grab throttle. Thus static-window ring reads can approach 20 iterations and 80 small GDI copy operations per second before overhead; this is a code-derived upper cadence, not a measured FPS or CPU benchmark. A full grab temporarily sets capture exclusion, waits another 50 ms, samples a 64-pixel-wide patch, restores affinity, hashes pixels, and emits a changed frame only to main. Capture API failures are largely ignored, including SetWindowDisplayAffinity's return, so exclusion success is not verified.

No source path was found that saves or networks these pixels. The frontend retains the raw frame plus small, previous, next and display canvases (`src/main.js:64-172`); “dropped on the next frame” simplifies the actual retention/crossfade. Blur defaults on (`main.rs:59`). Off/minimized skips new loop capture after the next check. Actual display-affinity behavior, GDI failure handling and resource use were not tested on screen.

### Collection, memory, filesystem and concurrency (F04, F10-F13, F16)

The token probe wrote 10,000 copies of `{"timestamp":"2000-01-01T00:00:00Z","tokens":{"total":10}}` to a newly created JSONL file. scan_tokens returned 10,000 entries for that file because its mtime was recent. Subsequent sum filters do not release those entries. Each changed file is reparsed from its start. Codex's limit of 20 files limits the number of reads, not file size, directory enumeration, sort size or total allocation. A valid limit line followed by byte 0xff caused the complete read_to_string to fail and the row to report “no limit data yet.” A buffered parser should tolerate an incomplete trailing record without discarding previously valid data.

The Windows traversal probe created only a root, a sibling containing marker.txt, and a junction from the root to that sibling. Exact baseline walk found the sibling marker through the junction. No user directories or credentials were involved. Because metadata follows links and no canonical/visited/depth check exists, selecting a linked tree can broaden the read boundary and create repeated traversal. resolve also accepts relative paths, treats any leading tilde as home-relative (including `~someone`), and falls back to an empty path if home discovery fails. These are additional path ambiguity/hardening issues; no arbitrary write outside the fixed settings path was established.

The notification receiver's deadline is not a hard work cap: after the 300 ms deadline, recv_timeout with zero remaining time still drains already queued items. A continuously replenished backlog can keep changed growing. No sustained event-flood or out-of-memory test was run. Deleted-file entries and old timestamp tuples have no periodic pruning path. Bounded memory and progress should be explicit invariants.

Lock scope is visible in emit: the guard survives both SQLite aggregates and all token summation before the snapshot is cloned. opencode_row is also redundantly queried by watcher work and then emit. SQLite busy_timeout is 500 ms (`main.rs:259`), but that does not bound full query CPU time, directory walking or log parsing under apply's lock. A blocked get_settings/get_usage or blur thread can therefore share one slow storage bottleneck. The ticker also polls due online providers serially (`main.rs:752-754`), so one slow provider delays later providers and emissions. No precise latency bound is claimed.

A synthetic mutex panic was caught and the subsequent lock returned PoisonError, verifying the standard mechanism behind F10. The application consistently unwraps lock results. This demonstrates a conditional failure cascade, not that normal production data already triggers a panic. Checked/overflow-safe token addition should also be tested: accepted u64 counters are summed without a bound.

For F13, poll records last only when it completes, and no in-flight flag exists. A sufficiently slow startup poll can overlap a ticker poll; successive settings changes also spawn workers. Newer-success then older-success overwrites newer data because directory equality has no sequencing information. A small deterministic model reproduced A -> B -> A accepting an old A result; it was a model of the source checks, not a running Tauri scheduler test. Watcher work has an even weaker commit condition: it checks connected/cache presence, not the generation of the directories it read. A completion also removes dirty before checking directory equality, so an obsolete request can clear a new activity marker.

For F16, interrupting a settings write after truncation is enough to reach load_settings's default branch on restart. Settings changes are applied and persisted without an atomic transaction or generation; source inspection, not a forced process crash, establishes this window. If configuration parsing fails, preserving disabled-provider choices is preferable to silently reverting ProviderCfg.enabled to true.

## Credential and security-claim review

- Credentials are read from Claude's credential JSON/macOS Keychain, Codex auth.json, Copilot apps.json **and hosts.json**, and Cursor's SQLite store (`main.rs:295-307`, `:340-347`, `:362-379`, `:403-415`). Fixed request URLs match the provider hosts listed by the README. Values are placed in authorization headers or Cursor's cookie. No direct application code was found writing credentials, emitting them in snapshots, or deliberately logging header/cookie values. Tokens remain ordinary allocated Strings/JSON values until dropped, without explicit zeroization; that alone is not evidence of durable credential leakage.
- Cursor's JWT payload is decoded without verifying a signature to construct its provider cookie. The server still must authenticate the submitted token; this decode is not evidence of an authentication bypass. Copilot discards credential-map keys and tries every oauth_token against the public GitHub endpoint. Account/host provenance should be preserved so enterprise or unrelated entries in an overridden file cannot be misrouted. No real token was used to test this risk.
- detect invokes all credential readers even for disabled providers (`main.rs:149-158`, `:774`, `:809`). Disabling avoids newly selected network polls, but does not guarantee no local credential access. An already started poll is not cancelled on disable. README:59's “stop its request entirely” needs this qualification.
- “Prompts and replies are never parsed, stored” (`README.md:80`) is too strong. Whole log contents are read into Strings, and selected lines are parsed as complete serde_json Values before extracting numeric fields. That includes any other fields on those lines. The durable token cache stores numeric tuples; no prompt transmission path was found. The problem is transient overcollection and an inaccurate absolute claim, not demonstrated remote collection.
- “At most one ... every refresh interval” (`README.md:67`) conflicts with dirty-provider polling at 120 seconds, multiple Copilot credential attempts, and overlapping polls. No telemetry/update-check implementation was found in the scoped source. Dependency redirects, system proxies, transport error redaction and all transitive behavior were not independently tested; fixed URL literals alone cannot prove every network destination invariant.
- Databases are opened read-only (`main.rs:256-260`). Settings writes target the app config directory, but use direct non-atomic writes. README's screen-bounds assurance is contradicted by F08. Its assurance about user/file content being absent from HTML omits the provider-derived status sink in F07; a user-controlled or local-file-controlled path to that sink was not established. The absence of plugin permissions does not replace validation of custom commands.

## Remaining limitations and repair order

No live provider request, authenticated endpoint contract comparison, actual screen capture, packaged WebView CSP execution, macOS/Linux runtime, installer signing verification, race stress test, resource exhaustion, fuzzing, or transitive dependency security assessment was performed. “Undocumented” is supported by the code's private-looking paths and README's explicit acknowledgment; the availability of every current vendor documentation page was not independently researched. No external source was needed to reproduce the implementation defects. Tests on copied pure functions do not validate Tauri wiring or native capture behavior.

First repair stale/expired/error display semantics and schema validation (F03, F05, F06, F09, F14), then remove the HTML sink and correct capture bounds/disclosure (F07, F08). Follow with bounded off-lock collection and versioned commits (F04, F10-F13, F15-F16), then consolidate provider interfaces, CI and security documentation. A passing existing suite is compatible with every demonstrated defect; the new regression scenarios must enter the maintained suite before treating those areas as covered.
